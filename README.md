# Herald

Notification broker for independent products. Authenticated producers publish
messages; Herald routes them to subscribed devices, retries delivery and records
acknowledgements. Android apps use FCM; browsers use Web Push with per-application
VAPID keys. Product logic and notification preferences belong to the product.

## Run locally

Requires Docker with Compose. Copy `.env.example` to `.env`, generate an
encryption key and set it in `.env`:

```sh
go run ./cmd/heraldctl keygen
docker compose up --build -d --wait
curl --fail http://localhost:8080/health
```

The Compose example runs an independent database and applies migrations before
starting the broker. Its credentials are for local development. Configure your
own production database, secrets, HTTPS and allowed origins before deployment.

For development without the app container, use `compose.test.yaml` and set
`DATABASE_URL` to its local database. `make run` starts the broker.

## Provision an application

Enable the admin UI using `ADMIN_USERNAME`, an Argon2id `ADMIN_PASSWORD_HASH`
generated by `heraldctl hash-password`, and exact `ADMIN_ORIGIN`. The CLI also
supports provisioning:

```sh
docker compose exec herald ./heraldctl create-application \
  -slug sample -name 'Sample App' \
  -origin https://app.example.com -subject mailto:ops@example.com
docker compose exec herald ./heraldctl create-producer \
  -application sample -name sample-api
```

Store returned credentials privately. Create topic IDs in the application's
routing catalog before publishing notifications to those topics.
